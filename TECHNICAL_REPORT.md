# Technical Report — GRADE & RoB2 RAG Chatbot System

**Date:** 2026-05-30  
**Stack:** Python 3.11, LangChain, FAISS, Gradio 5, OpenRouter  
**Authors:** Martyna Baran

---

## 1. Project Goal

Build a question-answering system grounded strictly in two medical methodology corpora:

- **GRADE** (Grading of Recommendations, Assessment, Development and Evaluations) — a framework for rating certainty of evidence and strength of recommendations in clinical guidelines
- **RoB2** (Cochrane Risk of Bias 2.0) — a structured tool for assessing bias in randomised trials

The system must never fabricate information beyond what the source documents contain. It serves diverse audiences — clinicians, policy makers, and laypeople — and includes automated quality evaluation.

---

## 2. Architecture Overview

The system follows a classic RAG (Retrieval-Augmented Generation) pattern without any agent framework:

```
Source documents (web + PDF)
        ↓
  scrape_and_chunk / load_pdfs_and_chunk
        ↓
    build_index (FAISS + HuggingFace embeddings)
        ↓  [cached to disk]
  similarity_search (top-k chunks)
        ↓
  LLM prompt (system + history + context + question)
        ↓
      Answer + Sources
```

All core logic lives in `rag_core.py`. `app.py` handles only the UI layer. Evaluation notebooks are fully independent and call `rag_core` functions directly.

## 3. Data Sources

### GRADE
- 8 pages from `book.gradepro.org` (scraped with headless Chrome + Selenium)
- PDF collection in `data/grade_pdfs/` (optional, parsed with SciPDF)

### RoB2
- Official Cochrane RoB2 guidance pages
- PDF collection in `data/rob2_pdfs/`

### Scraping
`fetch_visible_text(url)` launches headless Chrome via `webdriver-manager`, waits 5 s for JS rendering, strips nav/footer/script tags with BeautifulSoup, and returns clean visible text. Each page takes ~5–8 s.

## 4. Indexing Pipeline

### Chunking
Text is split into overlapping character-level chunks (default: 800 chars, 100-char overlap) by `chunk_text()`. Each chunk becomes a LangChain `Document` with metadata:
- `source` — originating URL or filename
- `source_type` — `"web"` or `"pdf"`
- `chunk_index` — position within the source

### Embeddings
`sentence-transformers/all-MiniLM-L6-v2` via `HuggingFaceEmbeddings` (runs locally, no API cost). A single shared instance is lazily loaded by `get_embeddings()`.

### Vector Store
Facebook FAISS (CPU). Built once with `build_index(docs)`, saved to `.faiss_cache/{domain}/`. On subsequent runs, `load_or_build_index()` checks a `source_state.json` file to decide whether to:
- **Load from cache** — sources unchanged
- **Append** — only new PDFs added, merge into existing index
- **Rebuild** — URLs changed or PDFs removed

### PDF Cache
Each PDF is parsed to JSON (`data/parsed_grade/`, `data/parsed_rob2/`) keyed by filename. Reparsed only if the source PDF is newer than its cache file.

## 5. RAG Answer Generation

### `rag_answer(query, index, llm, k=5)` → `(answer, contexts)`
Used exclusively by evaluation notebooks. Returns a 2-tuple. Do not change the return signature.

### `rag_answer_with_sources(query, index, llm, k=5, system_prompt, history)` → `(answer, contexts, sources)`
Used by the Gradio app. Extends `rag_answer` with:

1. **Query enrichment for retrieval** — last 2 user messages from `history` are prepended to the current question before calling `similarity_search`. This correctly resolves follow-up questions like "What about imprecision?" that would fail if sent to FAISS in isolation.

2. **Conversation history in prompt** — last 6 messages (3 full turns) are formatted as a `Conversation history:` block and injected between the system prompt and the retrieved context. Source blocks appended to assistant messages are stripped before inclusion to prevent prompt bloat. Long turns are truncated at 600 characters.

3. **Ordered source list** — `dict.fromkeys()` preserves retrieval order while deduplicating source identifiers.

### LLM
`ChatOpenAI` pointed at `https://openrouter.ai/api/v1`. All model names use OpenRouter format (`provider/model-name`). Temperature is fixed at 0.0 for deterministic answers. `build_llm(model_name=None)` accepts a direct model name to override the `MODEL_NAME` env var.

## 6. Gradio Web Application (`app.py`)

### Startup
At startup, both FAISS indices are loaded and the default LLM instance is created. Subsequent LLM instances (other models) are created on first use and cached.

### Per-Session Isolation
Every browser tab (connection) gets independent copies of all mutable state via `gr.State`:

| State variable | Content |
|---|---|
| `session_id` | UUID generated by `lambda: str(uuid.uuid4())` |
| `chatbot` | Full conversation history (Gradio messages format) |
| `last_qa` | Last question/answer/sources for feedback association |

This means two users on the same server cannot see each other's conversations.

### Audience Adaptation
A radio button selector at the top of each tab lets the user identify their background. The selection is stored in `gr.State` (per-session) and applied at request time by appending a `AUDIENCE_SUFFIXES[audience]` string to the base system prompt.

| Audience | Prompt instruction |
|---|---|
| 🩺 Expert | Use full technical terminology; skip basic explanations |
| 📋 Stakeholder | Explain technical terms briefly; focus on practical implications |
| 👤 Layperson | Plain language; define all jargon; use everyday analogies |

The selection can be changed mid-conversation and takes effect on the next message without resetting history.

### Model Selection
A second radio button group allows selecting the LLM model per session:

| Label | OpenRouter ID | Characteristics |
|---|---|---|
| ⚡ Gemini 2.5 Flash | `google/gemini-2.5-flash` | Default; best quality/cost balance |
| 🔬 Gemini 2.0 Flash Lite | `google/gemini-2.0-flash-lite` | Faster and cheaper |
| 🦙 Llama 3.1 8B | `meta-llama/llama-3.1-8b-instruct` | Open-source baseline |
| 🌬️ Mistral 7B | `mistralai/mistral-7b-instruct` | Lightweight, fast |
| 🔷 Qwen 2.5 7B | `qwen/qwen-2.5-7b-instruct` | Strong structured reasoning |

LLM instances are reused across requests via `_llm_cache` (dict keyed by label). Model changes take effect from the next message.

### Source Links
Every assistant reply ends with a `📚 Sources:` markdown block. Web sources are rendered as `[url](url)` clickable links; PDF sources as inline code. Sources are derived from chunk metadata populated during scraping/parsing.

### Feedback System
Gradio 5's built-in `chatbot.like()` event renders thumbs up/down on message bubbles (visible on hover). Clicking a thumb:
1. Reads the optional comment from the comment textbox
2. Calls `_save_feedback()` which appends a JSON line to `feedback.jsonl`
3. Updates a status label confirming the save

`feedback.jsonl` schema (one JSON object per line):
```json
{
  "timestamp": "2026-05-30T09:41:15+00:00",
  "session_id": "uuid",
  "domain": "GRADE | RoB2",
  "audience": "label",
  "model": "label",
  "question": "...",
  "answer": "...",
  "sources": ["url", ...],
  "rating": "up | down",
  "comment": "..."
}
```

## 7. Evaluation Pipeline

### Automated Metrics (`automated_evaluation_extended.ipynb`)

| Metric group | Metrics |
|---|---|
| RAGAS | Context Recall, Faithfulness, Factual Correctness, Answer Relevancy |
| Lexical | ROUGE-1, ROUGE-2, ROUGE-L, BLEU |
| Semantic | Cosine similarity (sentence-transformers) |
| Complexity | Flesch-Kincaid, sentence length, vocabulary richness |
| LLM-based | G-Eval (GPT-style scoring prompt) |

Results saved as CSVs in `evaluation_details/` following the naming pattern `{metric}_{chat_model}_{eval_model}.csv`.

### LLM Judge (`llm_judge.ipynb`)
Two independent LLM judges score each answer on Accuracy, Completeness, and Faithfulness (1–5 scale). Cohen's Kappa measures inter-judge agreement. Disagreements flag ambiguous questions.

### Human Evaluation (`prepare_human_eval.ipynb`)
Stratified sample of Q&A pairs exported to pre-filled CSVs for manual annotation. Annotation guide in `evaluation_details/human_eval/annotation_guide.md`.

## 8. Key Design Decisions & Rationale

| Decision | Rationale |
|---|---|
| No LangGraph | Original 4-node agent graph added complexity without measurable quality gain. Plain function calls in `rag_core.py` are easier to test, debug, and explain. |
| Two separate RAG functions | `rag_answer` keeps a stable 2-tuple signature for evaluation notebooks. `rag_answer_with_sources` adds features for the UI without breaking callers. |
| Character-level chunking | Simpler than sentence/paragraph splitting, predictable size, consistent behaviour across web text and PDFs. |
| FAISS CPU | Sufficient for corpora of this size (~hundreds of chunks). No GPU required, deployable on any machine. |
| OpenRouter | Single API key gives access to dozens of models (Google, Meta, Mistral, Qwen) without managing separate integrations. |
| Query enrichment with history | Appending prior user turns to the FAISS query is the simplest way to handle follow-up questions without a separate query-rewriting LLM call. |
| LLM cache | `ChatOpenAI` instances are lightweight but not free to construct. Caching by model label avoids redundant object creation across requests. |
| `gr.State` with lambda | `gr.State(lambda: str(uuid.uuid4()))` is the standard Gradio 5 pattern for per-session initialisation. Without the lambda, all sessions would share the same initial value. |
| JSONL for feedback | Append-only, human-readable, directly loadable with `pd.read_json(lines=True)`. No database required. |

## 10. Running the System

### First run (builds indices from scratch)
```bash
cp .env.example .env        # fill in OPENROUTER_API_KEY
pip install -r requirements.txt
python app.py               # indices built on first launch (~5 min for scraping)
```

### Subsequent runs (loads from cache, ~10 s)
```bash
python app.py
```

### Rebuilding an index
Delete the relevant cache directory and restart:
```bash
rm -rf .faiss_cache/grade
python app.py
```

### Analysing feedback
```python
import pandas as pd
df = pd.read_json("feedback.jsonl", lines=True)
df.groupby(["domain", "rating"]).size()
df.groupby(["model", "rating"]).size()
df[df["rating"] == "down"][["question", "comment"]]
df.explode("sources").groupby(["sources", "rating"]).size()
```
